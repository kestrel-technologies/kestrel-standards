# Perch · INC-0471 — Customer data exposure via Birdseye shared link

> Summary page. The ticket of record is Perch [INC-0471](https://github.com/kestrel-technologies/vantage-tickets/issues?q=INC-0471) in `vantage-tickets`.

**Ticket:** INC-0471 · **Severity:** SEV-2 (customer data exposure, no regulated data categories confirmed) · **Status:** Contained; RCA pending · **Opened:** 2026-09-28 14:12 PT by Owen Gallagher (VP CS & Support, Vantage) · **Incident Commander:** EntSec IR on-call (Lin Zhao's org) · **Business owner:** Dana Whitfield · **Related:** CHG-2291, WT-3317, ENTSEC-EXC-0890 (expired), KSS-REV-0419

## Summary

On 2026-09-17 a Vantage Support L2 engineer (Austin) pasted a link to a **Birdseye** customer-360 page into a public thread on the Vantage Support Portal while helping a customer. The link included a Birdseye session token in the URL. Birdseye is a legacy (Skyward-era) internal web application that reads account, contact, opportunity and case data from the Vantage production Salesforce org through an integration user.

The thread was publicly visible. Between 2026-09-17 and 2026-09-28 the link was opened from **37 distinct external IP addresses**. Each visitor who followed the link was authenticated as the engineer's Birdseye session and could browse Birdseye's customer search. Log analysis (Birdseye application logs; Salesforce login history for the integration user) indicates data for approximately **2,100 customer contacts across 64 accounts** was viewable, including names, business email addresses, phone numbers, open case subjects and opportunity amounts. No evidence of bulk export.

- No regulated data categories (payment, health, government ID) confirmed in scope; legal review ongoing.
- Reputational: Marcus Oyelaran briefed Amara Diallo (CEO, Kestrel Cloud) on 10-01.

## Contributing factors (as currently understood; not a root cause analysis)

1. Birdseye passes session tokens in URLs (design dating to 2017).
2. Birdseye sessions valid for 30 days with no re-authentication.
3. The Birdseye integration user's permissions exceeded what the application needs (details pending).
4. No centralized monitoring was in place for the Vantage production Salesforce org, so the anomalous access pattern from the integration user was not alerted on. **The org is not onboarded to Watchtower (see WT-3317).**
5. The engineer was not aware the portal thread was public.
